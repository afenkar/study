# AI 相关 · 前端向口述（约 10 题）

> 目标岗位：Vue/前端，**不是**训练模型、不是 LLM 研究员。  
> 面试官问的通常是：**你会不会用、敢不敢审、边界在哪**。  
> 用法：盖住口述稿说 45～60 秒 → 对照 → 勾选。

**现实里常见问法来源：** 行为面 / HR 加试、「你平时怎么写代码」、偶发「用 AI 改一段代码你怎么验收」、极少数公司有 vibe coding 机考。

---

## 先定调（30 秒开场，可复用）

> 我把 AI 当结对程序员：生成样板、解释陌生 API、帮我列边界情况；**业务逻辑、权限/Token、设备联调、性能和可维护性**必须自己把关。会用，但不把看不懂的代码直接合进去。

口诀：**提速样板 · 审生成物 · 守业务与安全**

---

## A. 工作流（最高频）

### AI-01 你日常怎么用 AI 写前端？
- [ ]

**口述稿：**  
我常用 Cursor / ChatGPT 这类工具。典型场景：脚手架和重复样板、正则/类型报错解释、把一段 Options 思路改成 Composition 草稿、帮我写单测骨架或 ESLint 规则示例。  
真正改 40WEB 这种设备网管时，我会先自己定接口约定和文件落点，再让 AI 补实现；生成完我对着页面和真机/联调结果验，不会「生成完就交」。

**要点：** 具体工具 + 具体场景 + 「自己定方案、AI 补实现、联调验收」。

**我的坑：** 别只说「用来查资料」——太虚；也别说「全靠 AI 写」——减分。

---

### AI-02 AI 擅长什么？你哪里不信任它？
- [ ]

**口述稿：**  
擅长：样板代码、API 用法、改写/重构草稿、从报错堆栈里猜方向、写文档和注释初稿。  
不信任：权限与 Token 处理、和设备 CGI/特殊协议强绑定的逻辑、随意改 Pinia 数据结构、无障碍语义、复杂竞态（比如我们切页 abort 那种）。  
行业报告也常提到生成代码有安全隐患比例不低，所以涉及鉴权、上传、跨端口（我们 1120）我一定人审。

**要点：** 两列清单 · 业务/安全/竞态不信任 · 和自己项目挂钩一句。

---

### AI-03 如果 AI 能生成组件，前端工程师还干什么？
- [ ]

**口述稿：**  
生成组件只是起点。工程师要做的是 AI 不好做的：选 Hash 还是 History、Token 放哪、请求要不要 abort、表头按机型怎么拆、包体积和设备性能能不能扛住。  
还有：读他人代码、查线上/联调问题、和后端/嵌入式对齐协议。判断力和责任边界才是岗位价值。

**要点：** 架构取舍 · 调试 · 对协议/性能负责。

## B. 验收与风险（容易追问）

### AI-04 拿到一段 AI 生成的 Vue 代码，上线前你怎么审？
- [ ]

**口述稿：**  
我会按清单过：  
1）有没有解构 `reactive` 丢响应式、该用 computed 却写成了 watch；  
2）列表 `key` 是否稳定；有没有直接改 prop；  
3）请求有没有遗漏 Token、错误是否乱弹 toast、组件卸载/切页是否还在更新；  
4）有没有把密钥写进前端、有没有不安全的 `v-html`；  
5）命名和目录是否符合我们项目（store / utils / views）。  
最后跑一遍关键路径，设备项目最好真机或同源 `/cgi` 验一下。

**要点：** 响应式坑 · 列表 key · 鉴权/取消 · 安全 · 项目约定 · 联调。

---

### AI-05 前端能不能把大模型 API Key 写进 Vue？
- [ ]

**口述稿：**  
不能把密钥打进前端包。浏览器里的东西用户都能看见。正确做法是前端打自家后端，由服务端持有 Key 再去调模型。  
我们设备网管本身也是前端只带业务 Token（`X-Token`），敏感能力在设备/服务侧。同一原则。

**要点：** Key 不进前端 · 走自有后端代理。

---

### AI-06 用 AI 时怎么处理公司代码/泄密？
- [ ]

**口述稿：**  
不确定工具是否合规时，不把完整业务代码、内网地址、账号密码、未公开协议贴进公网模型。  
能做的：脱敏后的片段、自己的学习仓库、通用 Vue/JS 问题。公司若提供企业版 Copilot/私有模型，再按制度用正式项目代码。  
Study 学习库和面试准备可以用 AI；40WEB 生产改动以本地规范和 Code Review 为准。

**要点：** 脱敏 · 合规 · 生产代码谨慎。

## C. 产品向（加分，不要求深）

### AI-07 若让你做「AI 对话/助手」前端，要注意啥？（口述架构即可）
- [ ]

**口述稿：**  
我会拆：消息列表（用户/助手气泡）、输入框、流式输出时的「正在生成」、中止生成、错误重试。  
流式用 SSE 或 fetch stream，逐 token 追加，注意别每个字都重渲染整棵大树；长列表可虚拟滚动。  
鉴权走自家后端；前端不存模型 Key。若嵌入我们网管，助手应只能调允许的配置查询，防止乱改设备参数。

**要点：** 流式 UI · 中止 · 性能 · Key 在服务端 · 权限边界。

---

### AI-08 听过 Prompt / RAG / Agent 吗？（一句话级）
- [ ]

**口述稿：**  
Prompt 就是给模型的指令和上下文，写清楚角色、约束、输出格式，结果更稳。  
RAG 是先检索公司文档/知识库再让模型答，减少胡编。  
Agent 是模型能多步调用工具（查接口、改文件），前端更多是展示进度和确认危险操作。  
我平时用工具时会写清约束；没在生产自研过 Agent，但知道边界。

**要点：** 各一句 · 诚实说深度 · 不装专家。

## D. 现场可能出现的考法

### AI-09 「打开 Cursor，一起做个小功能」你怎么表现？
- [ ]

**口述稿/策略：**  
先复述需求与验收标准 → 自己列文件/接口 → 再让 AI 生成 → **逐段讲我为什么改它**（比「生成很快」更重要）→ 自己跑一遍边界情况。  
面试官看的是：你会不会拆任务、会不会拒烂代码、会不会验证。

**要点：** 先规格后生成 · 边做边解释 · 手测。

---

### AI-10 结合 40WEB：AI 帮你提速过吗？举一例
- [ ]

**口述稿（按真实经历改）：**  
例如切页 timeout 那次：我自己定位是旧请求未取消，方案是 `AbortController` + 路由守卫重置；AI 更多帮我补工具函数骨架或对照 axios `signal` 写法，**竞态策略和静默错误是我定的**。  
再比如 ESLint flat config、防抖节流默写练习，会用 AI 出变体题，但默写必须自己过关——面试手写不能靠现场生成。

**要点：** 一例「我定方案 + AI 辅助实现」· 强调判断仍在自己。
